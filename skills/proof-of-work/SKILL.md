# Proof of Work

## Purpose

Capture professional evidence while the work is fresh.

This is not a generic activity summary.

## Inputs

Prefer:
1. worklogs
2. DECISIONS.md
3. STATE.md
4. Git commits/diffs
5. changed files
6. tests/builds
7. screenshots
8. deployments/live URLs
9. implementation docs
10. issue/task records

Discussion alone is not proof.

## Evidence standard

Separate:
- work performed
- evidence available
- verified result
- plausible business value

Never invent performance gains, conversion, revenue, traffic, user counts, time saved, rankings, or client outcomes.

## Achievement record

Store:

`_project-context/proof-of-work/achievements/YYYY-MM-DD-short-slug.md`

Template:

```markdown
# Achievement — Short title

Project:
Date:
Category:

## Problem
## Contribution
## Approach
## Result
## Verification
## Evidence
## Before / After
## Technologies
## Skills demonstrated
## Potential business value

## Reuse opportunities
- Portfolio:
- Case study:
- CV:
- Proposal:
- Client report:
- Content:

## Evidence gaps

Status: Verified | Partially verified | Unverified
```

## Weekly report

Create/update:

`_project-context/proof-of-work/weekly/YYYY/YYYY-WXX-proof-of-work.md`

Prefer 5 strong verified achievements over 30 weak observations.

## Safety

Read-first. Do not deploy, alter production data, rewrite source merely to improve the story, fabricate evidence, or publish externally without explicit instruction.
